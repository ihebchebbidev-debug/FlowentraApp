## Goal

Give each contact a unified **Activity** feed that automatically records every business event tied to them (offer created, sale confirmed, service order opened, dispatch scheduled, installation completed, …) alongside manual notes. Events are auto-generated by the backend so they appear on both the Activity tab and (as read-only system entries) in the Notes tab. All UI strings translated in EN/FR.

## What exists today (findings)

- `ContactNotesTab` supports **manual** notes only. No system writer anywhere (`ContactNoteService.cs` = 4 plain CRUD methods).
- Contact detail page has tabs for Overview / Installations / Offers / Sales / Service Orders / Notes. **No Activity tab is wired**, even though the locale key `detail.tabs.activity` already exists (orphaned).
- Offers/Sales already auto-log per-record activity (`OfferActivity`, `SaleActivity`) — we reuse the same pattern at the contact level.
- Offers, Sales, ServiceOrders, Dispatches, Installations all carry `ContactId` and support `?contactId=` filtering. Dispatch is currently **not surfaced anywhere** in the contacts module.
- No aggregated `GET /contacts/{id}/activity` endpoint exists.

## Design

### Backend (new `ContactActivity` table, mirrors `OfferActivity` pattern)

New model `Backend/Modules/Contacts/Models/ContactActivity.cs`:
```text
Id, ContactId (FK), Type (enum: NoteAdded, OfferCreated, OfferStatusChanged,
  SaleCreated, SaleStatusChanged, ServiceOrderCreated, ServiceOrderStatusChanged,
  DispatchCreated, DispatchStatusChanged, InstallationCreated, InstallationCompleted),
Description (short i18n key or template), RelatedEntityType, RelatedEntityId,
Metadata (json, e.g. amount, status), CreatedAt, CreatedByUserId, CreatedByName
```

New service `IContactActivityService` + `ContactActivityService` with:
- `LogAsync(contactId, type, relatedEntityType, relatedEntityId, metadata)`
- `GetByContactIdAsync(contactId, page, pageSize)`

New controller `ContactActivitiesController`:
- `GET /api/ContactActivities/contact/{contactId}` → paginated list

Inject `IContactActivityService` into and call `LogAsync` from:
- `OfferService.cs` — create (~L255) and status change (~L349, L806, L941)
- `SaleService.cs` — create (~L380) and status change
- `ServiceOrderService.cs` — create + status change
- `DispatchService.cs` — create (~L83) + status/assignment change
- `InstallationService.cs` — create (~L101) + completion
- `ContactNoteService.cs` — create/update/delete (so manual notes also appear in the unified feed)

Migration adds `ContactActivities` table with FK + index on `ContactId, CreatedAt DESC`.

### Frontend

1. **New Activity tab** `src/modules/contacts/components/detail/ContactActivityTab.tsx`
   - Chronological timeline; each row = icon (per type) + colored badge + description + relative time + "View" link to the related entity (offer/sale/etc.).
   - New hook `useContactActivity(contactId)` calling the new endpoint.
   - Empty state translated.
2. **Wire it up** in `ContactDetailPage.tsx`
   - Add `'activity'` first in `tabConfig`, `TAB_META.activity` entry, new `<TabsContent value="activity">`.
3. **Notes tab** — no schema change to `ContactNote`. System entries stay in `ContactActivity`; Notes tab keeps its current, purely-manual behavior. (Cleaner separation, avoids polluting notes with dozens of auto entries.)
4. **i18n** — add keys to `src/modules/contacts/locale/en.json` and `fr.json`:
   - `detail.activity.title`, `empty`, `view`, `loading`
   - `detail.activity.types.offer_created`, `offer_status_changed`, `sale_created`, `sale_status_changed`, `service_order_created`, `service_order_status_changed`, `dispatch_created`, `dispatch_status_changed`, `installation_created`, `installation_completed`, `note_added`, `note_updated`, `note_deleted`
   - Description templates use i18next interpolation, e.g. `"Offer {{number}} created ({{amount}})"` / `"Devis {{number}} créé ({{amount}})"`.
   - Add missing `detail.related.dispatch` label.

### Out of scope (unless you say otherwise)

- Backfilling historical activity for existing offers/sales/etc.
- Real-time push (SignalR) — the tab refetches on focus.
- Adding a Dispatch related-records tab (only surfaced via Activity for now).
